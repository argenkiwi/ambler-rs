Embed always rewrites state.embedding (None when nothing queued or host down) and Index::upsert treats None as keep the stored vector, so a title-only update keeps its vector and reindex never leaks a previous note's. Reindex's DetectChange must clear text_to_embed for unchanged notes. Note files are written with created/updated quoted (utils::notes::quote_timestamps) because serde_yaml leaves ISO timestamps bare, which other azk readers parse as dates. Index link inserts are INSERT OR IGNORE so link twice is idempotent.
