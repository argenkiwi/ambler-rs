The spec leaves resolveKhinsiderUrl undefined. utils::khinsider::resolve fetches the song page and takes its <audio src>, then falls back to the first .mp3 (then .flac) anchor, joined against the page URL. Links back to the page itself are skipped: every song page has a ?theme=dark anchor whose path ends in .mp3, and taking the first .mp3 anchor silently saved 13 KB HTML pages as audio (found only by running a real playlist, flow.m3u). The HTML parsing is a pure fn tested on fixtures, so a change to khinsider markup is fixed in that one place. Download filenames come from the percent-decoded last URL path segment reduced with Path::file_name, so an encoded ../ cannot escape the output folder. Repeated names get a numbered suffix (1.mp3, 1 (2).mp3), compared case-insensitively; DownloadFiles assigns every target path before any download starts, because parallel downloads to one name would race. The output folder is the playlist path without extension, beside the playlist; the original m3u is only removed after every download succeeded.
