The pide walk (specs/pide.md, src/walks/pide.rs, binary src/bin/pide.rs) sets up a containerised Pi agent for any project. Everything goes under <target>/.pide/. The Containerfile is the only input to the image: the build context is .pide/ itself, not the project. The pi/ folder is mounted at /root/.pi/agent instead of being baked in, so changing the server or model never forces a rebuild. Both the workspace and pi agent volume mounts must use the :z flag; without shared SELinux relabelling, Pi fails on startup with EACCES when creating /root/.pi/agent/sessions/--workspace--. The image name is pide-<folder>-<path hash>. It is rebuilt only when the Containerfile's sha256 differs from the image's pide.containerfile-hash label. Engine: podman if installed, otherwise docker. If the preferred engine is installed but not running, pide fails rather than falling back. The model list comes from <url>/v1/models (Ollama and LM Studio both serve it). The saved URL rewrites localhost/127.0.0.1/[::1] to host.docker.internal, and Launch passes --add-host host.docker.internal:host-gateway. Launch treats exit codes 125-127 as engine failures and every other code (including Pi's Ctrl-C) as a normal exit. Failures the user should see are recorded in state.error and routed to the FAIL node. run() then returns Error::Failed, and the runner exits 1 without printing again. Only unexpected I/O errors (stdin, writing pide's files) propagate as walk errors. Pi config gotchas (supportsDeveloperRole:false, safe.directory /workspace) come from the devenv/pi-sandbox prototype, commit d68c637.
