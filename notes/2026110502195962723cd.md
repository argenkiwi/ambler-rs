devenv.nix gives the host the nixpkgs Rust toolchain and `pi`/`sandbox-shell`/`sandbox-build` scripts. These run @earendil-works/pi-coding-agent inside the `ambler-rs-pi` image built from sandbox/, because Pi runs tools without asking. This is a port of the same setup in ambler-ts. The Pi config gotchas are identical there: defaults go in the agent-dir settings.json baked into the image, Ollama needs supportsDeveloperRole:false, and git safe.directory is set for /workspace. Rust-specific points: (1) the image, the sessions volume and the cache volumes are prefixed `ambler-rs-`. Both repos mount at /workspace, and Pi keys sessions by cwd, so shared names would mix them up. (2) The container builds into CARGO_TARGET_DIR=/cargo-target on a volume, and the registry is cached on another volume. Linux artifacts never land in the host's ./target, so macOS builds stay incremental. (3) The image is FROM rust:<ver>-slim-bookworm, with RUST_VERSION taken from the host `rustc` by sandbox-build. Node is copied in from node:24-bookworm-slim. The slim image installs rustup's minimal profile, so clippy and rustfmt are added explicitly. (4) azk is a macOS binary and isn't available in the container.
