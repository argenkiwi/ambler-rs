The walk-runner convention only finds a walk run from src/main.rs or src/bin/, so dispatching verbs from library code (src/cli.rs calling walks::<verb>::run) produced false violations. Rather than widen the rule, the CLI is a single cli walk (src/walks/cli.rs, specs/cli.md) mirroring ambler-ts: a Route node consumes the verb and branches to PlanNode/PlanWalk/PlanUtil/Inspect/Help, with every failure going to one Report node. Because one Report serves all verbs, the exit code (1 or 2) is recorded in state (HasExitCode) by whichever node fails; plan nodes return a scaffold::Rejection (Exists = 1, Invalid = 2) instead of the old message.contains("already") heuristic. walks::cli::run returns ExitCode directly (walk-surface allows only Error and run), and ambler::cli::run is a pub use of it so xtask crates keep working. State stays in walks/mod.rs because testing.rs needs it and a pub(crate) item in a walk file breaks walk-surface. Route is pure, so it has no Utils/SystemUtils: node-shape only requires SystemUtils when a Utils trait exists.
