The `state-traits` rule in src/scaffold/rust/lint.rs makes the state registry the only place a `trait Has<Field>` may be declared, and limits each trait to `fn <field>(&self)` plus an optional `fn <field>_mut(&mut self)`. Read-only traits are allowed on purpose: a field nodes only read should not offer a mutable accessor. The rule exists because the walk scaffolder (`source.rs::state_traits`) builds a walk's State from the registry alone, so a grouped trait (two fields), a behaviour method or a trait in another file silently breaks generated State impls. A trait counts as a state trait only when `Has` is followed by an uppercase letter, so `Hash`-like names are not flagged. The rule scans every src/**/*.rs with a syn visitor (including inline modules) and skips files that do not parse, since `parse` is reported elsewhere. The optional check that nodes use no non-Has trait as a state bound was not implemented. Field name is `names::snake` of the suffix, so acronym suffixes (HasHTTPUrl) would expect h_t_t_p_url: name fields in plain PascalCase.
